# `@texuli/pages/i18n/es`

A Spanish dictionary for every `@texuli/pages` label (ADR-026): the
editor's toolbars, slash menu and announcements, the reader's outline, the
paged view and the review UI (comments, suggestions, version history).

> **Status: new in `0.14.3`; in development.** The translations have not
> had a native-speaker review yet. They aim at a neutral Latin American and
> international product register (tú, infinitive buttons such as
> "Cancelar" and "Guardar"); report wording that reads wrong.

```svelte
<script lang="ts">
  import { BLOCKS_LABELS_ES } from '@texuli/blocks/i18n/es';
  import { PAGES_LABELS_ES } from '@texuli/pages/i18n/es';
  import { LabelsProvider } from 'texuli/i18n';
  import { TEXULI_LABELS_ES } from 'texuli/i18n/es';

  const es = { ...TEXULI_LABELS_ES, ...BLOCKS_LABELS_ES, ...PAGES_LABELS_ES };
  let { children } = $props();
</script>

<LabelsProvider labels={es} locale="es">
  {@render children()}
</LabelsProvider>
```

## API

- `PAGES_LABELS_ES` is a frozen `Readonly<Record<PagesMessageId, string>>`
  with every id of `PAGES_MESSAGES_EN` (from `@texuli/pages`) in Spanish.
  Its `{placeholders}` are the English ones, unchanged. A label prop on a
  component (`labels`) still wins over it; spread your own overrides after
  it to change a few words.
- Opt-in: no other entry imports it, so a page that does not import this
  subpath does not carry the Spanish text.
- A type check keeps it complete: when `PAGES_MESSAGES_EN` gains or loses
  an id, `pnpm --filter @texuli/pages typecheck` fails until this catalog
  follows; `packages/pages/tests/labels.test.ts` checks the ids and the
  placeholders too.

The `texuli` and `@texuli/blocks` catalogs, and how the dictionary
resolves, are in [texuli i18n](https://github.com/DailybotHQ/texuli/blob/main/packages/texuli/docs/i18n.md#spanish-catalogs-es).
