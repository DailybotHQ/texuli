# Component messages (i18n)

> **Status: new in 0.8.0** (ADR-016). English is the default; from
> `0.14.3` an opt-in Spanish catalog ships for `texuli`, the primitives,
> `@texuli/blocks` and `@texuli/pages` ([Spanish catalogs](#spanish-catalogs-es),
> not reviewed by a native speaker yet). Other languages are planned; hosts
> can load their own catalogs today.

**Package:** `texuli` · **Import:** `import { setI18nContext, useMessages, TEXULI_MESSAGES_EN } from 'texuli'`; `import { LabelsProvider, setTexuliLabels } from 'texuli/i18n'`

Every label a styled component writes itself (close buttons, empty and
error states, navigation names, carousel and command palette text…)
resolves through the [`@texuli/core/i18n`](../../core/docs/core-i18n.md)
message catalog, in this order:

1. the **instance prop** when you set one (`closeLabel="Shut"`, or a key of
   a `labels` object): existing props keep working and always win;
2. the **catalog in context**: the active locale, then its base language;
3. the component's **English default**.

```svelte
<script lang="ts">
  import { createI18n } from '@texuli/core/i18n';
  import { setI18nContext } from 'texuli';

  const i18n = setI18nContext(
    createI18n({ locale: 'en', loaders: { 'pt-BR': () => import('./locales/pt-BR.ts') } })
  );
</script>
```

| Export | What it does |
| --- | --- |
| `setI18nContext(i18n)` | Puts one `I18n` in Svelte context for every component below (call it in a component's script); returns it. The context key is `@texuli/core/i18n`'s `I18N_CONTEXT`, so `@texuli/primitives` reads the same catalog |
| `getI18nContext()` | The `I18n` in context, or `undefined` |
| `useMessages()` | The component-side `MessageLookup` (`(id, english, values) => string`, plus `has(id)`): reactive in `$derived` and markup, so labels update when the locale or catalogs change (lazy locales included); English only when no `I18n` is in context. Call during component initialization |
| `TEXULI_MESSAGES_EN` | Every styled component label id (`texuli.<component>.<label>`, such as `texuli.dialog.close-label`) with its English default: the catalog a translation starts from. Components keep their defaults inline, so tree shaking still works; a test keeps this catalog equal to them |

## One dictionary for every package (ADR-026)

> **Status: new in `0.13.0`.** On
> `0.12.3` and earlier, `createI18n({ locale: 'es', catalogs: [{ locale: 'es', messages }] })`
> with `setI18nContext` already translates the `texuli` and primitives labels.

A product in one language does not need catalogs and loaders: pass one flat
dictionary of message ids once, near the root, and every built-in label of
`texuli`, `@texuli/primitives`, `@texuli/blocks` and `@texuli/pages`
follows it. The order per label stays the same: the component's own prop,
then the nearest dictionary, then an outer one, then English.

```svelte
<!-- App.svelte -->
<script lang="ts">
  import type { BlocksMessageId } from '@texuli/blocks/i18n';
  import type { LabelDictionary } from '@texuli/core/i18n';
  import type { PagesMessageId } from '@texuli/pages';
  import type { TexuliLabels } from 'texuli';
  import { LabelsProvider } from 'texuli/i18n';

  const es: TexuliLabels & LabelDictionary<BlocksMessageId | PagesMessageId> = {
    'texuli.dialog.close-label': 'Cerrar',
    'texuli.toaster.label': 'Notificaciones',
    'texuli.combobox-empty.announce': 'Sin resultados',
    'texuli.content-layout.on-this-page': 'En esta página',
    'primitives.pagination.label': 'Paginación',
    'primitives.pagination.page-label': 'Página {page}',
    'blocks.text.tones.info': 'Información',
    'blocks.text.tones.warning': 'Advertencia',
    'pages.outline': 'En esta página',
    'pages.moved': '{label} movido a la posición {position} de {total}.',
  };
  let { children } = $props();
</script>

<LabelsProvider labels={es} locale="es">
  {@render children()}
</LabelsProvider>
```

| Export | What it does |
| --- | --- |
| `LabelsProvider` (`texuli/i18n`) | Props `labels` (a `LabelDictionary`), `locale` (BCP 47, default `en`: plural rules and number formatting in messages) and `children`. Renders no element. Changing `labels` or `locale` updates every label in place; nested providers layer (the inner one wins for its ids) |
| `setTexuliLabels(labels, options)` (`texuli/i18n`) | The same from a component's script (`TexuliLabelsOptions`: `locale`); returns the `I18n` it put in context. A host with only `@texuli/primitives` writes `setI18nContext(createLabels(labels, { locale }))` |
| `TexuliLabels` | `LabelDictionary<TexuliMessageId \| PrimitivesMessageId>`: every id of this package and the primitives, each optional |
| `TexuliMessageId` | The union of `TEXULI_MESSAGES_EN`'s ids |

Where the ids are:

| Package | English catalog | Id union |
| --- | --- | --- |
| `texuli` | `TEXULI_MESSAGES_EN` | `TexuliMessageId` |
| `@texuli/primitives` | `PRIMITIVES_MESSAGES_EN` | `PrimitivesMessageId` |
| `@texuli/blocks` | `BLOCKS_MESSAGES_EN` (`@texuli/blocks/i18n`) | `BlocksMessageId` |
| `@texuli/pages` | `PAGES_MESSAGES_EN` | `PagesMessageId` |

Start a translation from those catalogs: copy the ids, translate the
values, and keep `{placeholders}` as they are. Messages may also be plural
or select objects (see [core i18n](../../core/docs/core-i18n.md)), formatted
with the dictionary's locale. Number and date components keep their own
`locale` props. The root `texuli` entry exports the types only, so an app that never sets a
dictionary does not carry the catalog runtime. Not covered yet: `@texuli/data`, `@texuli/chat`,
`@texuli/media` and `@texuli/editor` defaults still need their `labels`
props (planned).

## Spanish catalogs (`es`)

> **Status: new in `0.14.3`.** The translations have not had a
> native-speaker review yet. They aim at a neutral Latin American and
> international product register (tú, infinitive buttons such as
> "Cancelar", "Guardar" and "Cerrar"); report wording that reads wrong.

Three opt-in subpaths hold a Spanish value for every id of the English
catalogs above. Nothing imports them by default, so the root entry and the
other subpaths do not carry the Spanish text; import only the packages you
render:

| Subpath | Export | Ids it covers |
| --- | --- | --- |
| `texuli/i18n/es` | `TEXULI_LABELS_ES` | every `TexuliMessageId` and `PrimitivesMessageId` (the `TexuliLabels` set) |
| `@texuli/blocks/i18n/es` | `BLOCKS_LABELS_ES` | every `BlocksMessageId` |
| `@texuli/pages/i18n/es` | `PAGES_LABELS_ES` | every `PagesMessageId` |

```svelte
<script lang="ts">
  import { BLOCKS_LABELS_ES } from '@texuli/blocks/i18n/es';
  import { LabelsProvider } from 'texuli/i18n';
  import { TEXULI_LABELS_ES } from 'texuli/i18n/es';

  // Spread your own words after a catalog to change a few labels.
  const es = { ...TEXULI_LABELS_ES, ...BLOCKS_LABELS_ES, 'texuli.app-nav.label': 'Menú' };
  let { children } = $props();
</script>

<LabelsProvider labels={es} locale="es">
  {@render children()}
</LabelsProvider>
```

Each catalog is a frozen plain object (`Readonly<Record<Id, string>>`), so
it also works as the `messages` of a `MessageCatalog`:
`createI18n({ locale: 'es', catalogs: [{ locale: 'es', messages: TEXULI_LABELS_ES }] })`.
Every `{placeholder}` is the English one, unchanged; the ids that come in
`-one` and `-other` pairs (such as `blocks.diagram.flow-summary-one`) hold
the Spanish singular and plural. A type check (`satisfies` against the id
union) fails when an English id is added or removed and the catalog does
not follow, and the tests check the ids and placeholders again
(`packages/texuli/tests/i18n.test.ts`,
`packages/blocks/tests/i18n.test.ts`,
`packages/pages/tests/labels.test.ts`).

Messages are always rendered as text, never markup. Function labels (such
as a tag's remove label) take their arguments as `{0}`, `{1}`… when a
catalog translates them. Without an `I18n` in context the components cost
only their inline English strings.

Tests: `packages/texuli/tests/i18n.test.ts` (catalog coverage under the
pseudo-locale, resolution order, live locale changes, `LabelsProvider`
precedence, nesting and updates, `setTexuliLabels`) and
`packages/pages/tests/labels.test.ts` (texuli, primitives, blocks and pages
rendered under a Spanish dictionary with no English default left).
