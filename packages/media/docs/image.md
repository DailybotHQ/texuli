# Image

`Image` renders one picture safely. It covers:

- a responsive `srcset` (explicit, or generated by a loader);
- a focal point for crops;
- blur-up or color placeholders;
- lazy loading by default;
- a labeled fallback when a source is blocked or fails.

Every URL passes the core image policy (`safeImageSrc`, `safeImageSrcset`).
Added by T-media-image.

```svelte
<script lang="ts">
import { Image } from '@texuli/media/image';
</script>

<Image
  src="https://images.example.com/harbor.jpg"
  widths={[480, 960, 1600]}
  loader={(src, width) => `${src}?w=${width}`}
  sizes="(min-width: 48rem) 40rem, 100vw"
  alt="Fishing boats in a harbor at sunset"
  width={1600}
  height={900}
  focalPoint={{ x: 0.27, y: 0.6 }}
  placeholder={{ kind: 'blur', src: 'https://images.example.com/harbor.jpg?w=16' }}
/>
```

## Props

| Prop | Default | Notes |
| --- | --- | --- |
| `src` | — | Untrusted by default: HTTPS or a relative path. |
| `alt` | — | Required. `""` marks the image decorative. |
| `srcDark` | — | New in `0.13.1`. The image for dark mode. It passes the same policy at the same `trust` tier, shares `alt`, and gets a srcset from `widths` + `loader` (an explicit `srcset` applies to `src` only). A blocked `srcDark` leaves the light image alone. See [Light and dark pair](#light-and-dark-pair). |
| `darkMode` | `theme` | New in `0.13.1`. `theme`: follow the page's color mode. `system`: follow the OS preference only. |
| `srcset` | — | Validated as a whole: one unsafe candidate drops the set. |
| `widths` + `loader` | — | Generate `srcset` from `src`. Widths are deduplicated, sorted and capped at 16. Every generated URL must pass the policy, or the whole set is dropped; a throwing loader also drops it. |
| `sizes` | — | Media conditions and lengths only. It is dropped when there is no srcset. |
| `width`, `height` | — | Positive integers ≤ 16,384. They set `aspect-ratio` (no layout shift) and cap the box at `min(100%, width)`. |
| `fit` | `cover` | `cover`, `contain`, `fill`, `none` or `scale-down`. |
| `focalPoint` | center | `{ x, y }` from 0 to 1, clamped, used as `object-position`. Image coordinates are physical, so it is not mirrored in RTL. |
| `placeholder` | none | `{ kind: 'color', color: '#hex' }` paints the box while loading. `{ kind: 'blur', src }` shows a tiny image blurred until the full one loads, then fades it out (instantly under reduced motion). The blur `src` passes the same policy. |
| `loading` | `lazy` | `lazy` or `eager`. |
| `fetchPriority` | `auto` | `high`, `low` or `auto`. |
| `trust` | `untrusted` | `developer` also allows HTTP, blob URLs and bounded base64 raster data images. |
| `href` | — | Wraps the image in a link, through `safeHref(href, trust)`. The same `trust` tier as `src` applies: untrusted allows `https:`, `mailto:` and `#fragment` only; developer also allows relative and `http:` app links. An unsafe href leaves a plain image. |
| `onactivate` | — | Wraps the image in a native `<button type="button">`. |
| `actionLabel` | — | Accessible name for the link or button. Needed when `alt` is `""`. |
| `labels` | English | `{ unavailable }`: the visible fallback text. |
| `class` | — | Svelte class value (string, array or object), on the image box. |
| `onload`, `onerror`, `onstatus` | — | `onstatus` receives `loading`, `loaded`, `error` or `blocked`. |

## Behavior

- **Attributes.** The `img` always has `decoding="async"`. Untrusted images
  get `referrerpolicy="no-referrer"`.
- **Status.** The box carries `data-status` and `data-fit`. A new `src`
  starts again at `loading`.
- **Cached images.** An image that finished before the listeners attached is
  detected (`complete` and `naturalWidth > 0`).
- **Fallback.** A blocked source (policy) or a failed load renders a box
  with the visible `labels.unavailable` text.
  - With an `alt`, the box is `role="img"` named by the `alt`.
  - A decorative image's fallback is `aria-hidden`.
  - Blocked sources are never requested: a browser check verified that no
    request leaves the page origin.
- **Keyboard.** Link and button images are native elements, so Tab, Enter
  and Space work. They use the token focus ring
  (`--tx-ring`, `--tx-focus-ring-width`, `--tx-focus-ring-offset`).
- **CSS.** The component's CSS sits in `@layer tx.components`, so consumer
  classes win. It uses logical properties only.
- **Tokens.** `--tx-muted`, `--tx-muted-foreground`, `--tx-border-strong`,
  `--tx-radius` and `--tx-motion-*`. Each has a system-color fallback, and
  forced colors map to `Canvas` / `CanvasText`.

## Light and dark pair

New in `0.13.1`. One image with a light and a dark source:

```svelte
<Image src="/brand/logo-light.svg" srcDark="/brand/logo-dark.svg" alt="Harbor Studio" />
```

- **`darkMode="theme"` (default).** Both images render, and CSS shows one.
  The nearest color-mode scope picks it: a `.dark` or `.light` class, or
  `data-tx-mode="dark"` / `"light"` (what `applyColorMode` and `applyTheme`
  write). A forced mode wins over the OS preference, and nested scopes work,
  because the choice is two inherited custom properties set on each scope.
  Without a scope, `prefers-color-scheme` decides.
- **`darkMode="system"`.** One `<picture>` with a
  `<source media="(prefers-color-scheme: dark)">`. The browser downloads only
  the image it shows, but an explicit theme switch on the page is ignored.
  Use it when the page always follows the OS.
- **Downloads.** In `theme` mode, keep the default `loading="lazy"`.
  Chromium and WebKit did not request a lazy image hidden with
  `display: none` (checked with Playwright), so only the shown image loads.
  With `loading="eager"`, both images download. If the theme changes later,
  the other image loads when it is first shown.
- **Accessibility.** In `theme` mode the box is the one `role="img"` named by
  `alt`, and both `<img>` carry `alt=""`. Only one image reaches assistive
  tech, with or without CSS. A decorative pair (`alt=""`) exposes nothing. In
  `system` mode the single `<img>` carries `alt`.
- **Status.** The first image to load sets `loaded`. In `theme` mode, a load
  error on the image the theme hides is ignored.

The `media-image-dark` example shows the page-theme pair, a forced dark
scope and a forced light scope on the same page, and the `system` picture.
`tests/e2e/media-image-dark.spec.ts` checks which image shows for each OS
preference and page mode in Chromium, WebKit and the Pixel 7.

## Examples

`media-image` (`packages/examples/src/media-image/`) shows:

- a responsive hero with a blur-up placeholder;
- two focal-point crops of the same picture, plus `fit="contain"`;
- a link image and a button image that toggles size;
- two blocked sources and one missing file.

The pictures are local fictional SVGs imported with `?url&no-inline`.
Vite would otherwise inline small assets as `data:` URLs, which the
untrusted policy rightly rejects.

**Verified in a browser** (scratch Playwright spec, Chromium and Pixel 7):

- axe found 0 violations in light and dark, with and without forced colors;
- keyboard reaches the link and operates the button with Enter and Space;
- no request goes to another origin;
- focal points stay physical in RTL;
- reduced motion removes the fade.

## Limits

- **No `<picture>` art direction or format switching.** That means no
  per-breakpoint sources and no AVIF/WebP `type` alternatives yet. The only
  `<picture>` is the `srcDark` one in `darkMode="system"`.
- **The loader is the host's job.** Texuli does not resize images.
- **Errors before hydration.** A load error that happened before the
  component mounted (server-rendered markup) is not detected, because a
  broken request also reports `complete`. Only successful early loads are
  detected.
- **Status is per source.** Starting a new source resets it. A late event
  from the previous source could be attributed to the new one.
