Usage: texuli <group> <verb> [--json <object> | --file <path>] [--out <path> [--overwrite]]
       texuli <command> [options]
       texuli help [<group>]

Operations (the @texuli/tools registry; the same names are MCP tools):
  catalog search      Search the component catalog
  catalog validate    Validate catalog manifests
  component get       Read a component manifest
  example search      Find component examples
  blueprint validate  Validate a blueprint draft
  block list          List block types
  block schema        Read a block shape
  theme search        Search the theme library
  theme get           Read a full theme
  theme preview       Preview a theme
  deck run            Run a deck command
  document run        Run a document command
  document export     Export a document as PDF or DOCX (node only)

Commands:
  deck <command>      The deck commands (capabilities, schema, layouts, lint, inspect, from-markdown, to-markdown)
  document <command>  The document commands (validate, patch, from-markdown, to-pdf … with --out)
  ds check <file>     Check a design-system document: codes, guarantees, contrast report (--json, --render, --mode, --variant)
  mcp                 Run the local MCP server over stdio (every operation)
  init                Wire Texuli tokens and CSS into a Vite, Astro or SvelteKit project
  theme list          List the theme library
  theme preview <id>  Show a theme's key tokens and its WCAG AA report
  theme apply <id>    Switch an initialized project to another theme
  add <component>     Copy a styled component's source into the app
  diff <component>    Show what an update of a copied component would change
  update <component>  Three-way merge a copied component with a new source

Input: one JSON object from stdin, --json <object> (--json - reads stdin) or --file <path>.
Output: JSON on stdout (exit 1 on a refusal), or --out <path> to write it to a new file inside the working directory (--overwrite replaces one).
Run texuli <group> --help or texuli <group> <verb> --help for details.

Usage: texuli catalog search [--json <object> | --file <path>] [--out <path>]

Search the component catalog (catalog.search, runtime edge)
Search the built, content-addressed Texuli component catalog by text, group and emit tier. Returns the catalog hash and file name, the match count and one summary per component (id, package, label, summary, tier, group, emit tiers).

Arguments (JSON object keys):
  query: string. Text to match against component ids, labels and summaries.
  group: string. An exact manifest group id, e.g. "display" or "forms".
  tier: "developer" | "untrusted". Keep only components this emit tier may place: untrusted is what agent output may use; developer is app-authored code.
  limit: integer. How many results to return (1 to 100, default 50).

Limits: input up to 4096 bytes, at most 100 items, 5000 ms budget.
Example (Cards an agent may place): texuli catalog search --json '{"query":"card","tier":"untrusted","limit":5}'

----
Usage: texuli catalog validate [--json <object> | --file <path>] [--out <path>]

Validate catalog manifests (catalog.validate, runtime edge)
Validate one candidate catalog manifest, or a set (which also catches duplicate ids), without writing files. Returns valid and a list of diagnostics, each with a code, a JSONPath, a message and a hint.

Arguments (JSON object keys):
  manifest: object. A candidate catalog manifest (id, package, label, summary, tier, props, examples …).
  manifests: array. A candidate manifest set (at most 500).

Limits: input up to 1000000 bytes, at most 500 items, 5000 ms budget.

----
Usage: texuli component get [--json <object> | --file <path>] [--out <path>]

Read a component manifest (component.get, runtime edge)
Read one component manifest from the catalog by id. Returns { component }: its props with kinds and schemas, events, worked examples, useWhen and dontUseWhen guidance, accessibility notes and the emit tiers that may place it (an empty emit list means agent output may not).

Arguments (JSON object keys):
  id (required): string. A catalog component id, e.g. "card" (find ids with catalog.search).

Limits: input up to 1024 bytes, 5000 ms budget.
Example (The card manifest): texuli component get --json '{"id":"card"}'

----
Usage: texuli example search [--json <object> | --file <path>] [--out <path>]

Find component examples (example.search, runtime edge)
Find worked manifest examples (props an agent can copy) by component id and/or example id, or search their titles and descriptions. Returns the match count and each example with its component id and package.

Arguments (JSON object keys):
  componentId: string. A catalog component id, e.g. "card" (find ids with catalog.search).
  exampleId: string. An exact example id within the component, e.g. "basic".
  query: string. Text to match against example ids, titles and descriptions.
  limit: integer. How many results to return (1 to 100, default 50).

Limits: input up to 4096 bytes, at most 100 items, 5000 ms budget.
Example (Every card example): texuli example search --json '{"componentId":"card"}'

----
Usage: texuli blueprint validate [--json <object> | --file <path>] [--out <path>]

Validate a blueprint draft (blueprint.validate, runtime edge)
Validate a blueprint draft (a catalog tree, an array of trees, or a texuli-blueprint envelope, migrated first) with the catalog's draft checks: structure, sinks, tree limits, component ids, tiers and prop schemas, deep block and document schemas, grammar and the frame root. Returns valid, status, tier, migratedFrom and diagnostics with the catalog's stable codes.

Arguments (JSON object keys):
  draft (required): object | array. The blueprint: a catalog tree { id, props, children }, an array of trees, or a texuli-blueprint envelope (format, version, id, catalog hash from catalog.search, status, createdAt, updatedAt, generator, tree). At most 512 nodes. schema-form, canvas and spreadsheet nodes and data-source bindings are refused: this server has no validator for them.
  tier: "untrusted" | "developer". The tier to validate at: untrusted (agent output, the default) or developer (app-authored). A tier the draft declares is ignored.
  fragment: boolean. Accept any roots (a fragment). Default false: one frame root (layout-page, layout-doc, layout-deck, document, canvas or data-dashboard).

Limits: input up to 270336 bytes, at most 512 items, 5000 ms budget.

Usage: texuli block list [--json <object> | --file <path>] [--out <path>]

List block types (block.list, runtime edge)
List the content block types the blocks-* components render (table, stat, cta, poll …), optionally for one component or matching words. Returns the match count and, per type, the component that renders it, a label and when to use it; read one shape with block.schema.

Arguments (JSON object keys):
  component: "blocks-text" | "blocks-data" | "blocks-media" | "blocks-diagram" | "blocks-embed" | "blocks-structure" | "blocks-code" | "blocks-interactive" | "blocks-map". Only the types this blocks-* component renders, e.g. "blocks-data".
  query: string. Words to match against the type, its label and its useWhen notes.

Limits: input up to 1024 bytes, at most 32 items, 5000 ms budget.
Example (What blocks-data renders): texuli block list --json '{"component":"blocks-data"}'

----
Usage: texuli block schema [--json <object> | --file <path>] [--out <path>]

Read a block shape (block.schema, runtime edge)
Read the shape of one content block type: the component that renders it, its fields as compact text and as a JSON Schema (required fields are the ones the validator refuses a block without), examples that validate in a blueprint, limits, when to use it and whether it can pass blueprint.validate today. Returns what a blocks-* node’s block prop needs.

Arguments (JSON object keys):
  type (required): "heading" | "text" | "list" | "quote" | "callout" | "table" | "stat" | "kpi" | "chart" | "image" | "figure" | "video" | "gallery" | "flow" | "tree" | "board" | "terminal" | "embed-app" | "link-preview" | "columns" | "grid" | "tabs" | "accordion" | "cards" | "divider" | "cta" | "code" | "poll" | "quiz" | "calculator" | "checklist" | "map". A block type from block.list, e.g. "table" or "cta".

Limits: input up to 1024 bytes, 5000 ms budget.
Example (The table block): texuli block schema --json '{"type":"table"}'

Usage: texuli theme search [--json <object> | --file <path>] [--out <path>]

Search the theme library (theme.search, runtime edge)
Search the Texuli theme library (200+ offline themes) by words, category, collection, mood or tag. Returns the match count and each theme’s metadata: id, name, description, category, collection, mood, tags, contrast level and whether it is dark-first.

Arguments (JSON object keys):
  query: string. Words that must all match the id, name, tags, mood, category, collection or description; results are ranked.
  category: string. An exact category, e.g. "Technology".
  collection: "industry" | "brand-like" | "high-contrast" | "colorblind-safe" | "seasonal" | "mono". One theme collection.
  mood: "calm" | "bold" | "playful" | "corporate" | "editorial" | "technical" | "warm" | "fresh" | "luxurious" | "minimal". One mood the theme must have.
  tag: string. An exact tag.
  limit: integer. How many themes to return (1 to 500, default 50).

Limits: input up to 4096 bytes, at most 500 items, 5000 ms budget.
Example (Violet themes): texuli theme search --json '{"query":"violet","limit":5}'

----
Usage: texuli theme get [--json <object> | --file <path>] [--out <path>]

Read a full theme (theme.get, runtime edge)
Read the full token definition of one library theme by id. Returns { theme }: its id, name, description and every light and dark color, radius, font and chart token, ready to compile or apply.

Arguments (JSON object keys):
  id (required): string. A theme id from theme.search, e.g. "violet" or "enterprise-neutral".

Limits: input up to 1024 bytes, 5000 ms budget.
Example (The violet theme): texuli theme get --json '{"id":"violet"}'

----
Usage: texuli theme preview [--json <object> | --file <path>] [--out <path>]

Preview a theme (theme.preview, runtime edge)
Preview one library theme in light or dark mode. Returns its summary, the key tokens of that mode (background, foreground, primary, border, radius, font …) and the WCAG 2.x AA contrast report for both modes (aa.pass and issue counts).

Arguments (JSON object keys):
  id (required): string. A theme id from theme.search, e.g. "violet" or "enterprise-neutral".
  mode: "light" | "dark". The mode whose tokens to show (default light); the AA report covers both.

Limits: input up to 1024 bytes, 5000 ms budget.
Example (Ocean in dark mode): texuli theme preview --json '{"id":"ocean","mode":"dark"}'

Usage: texuli deck run [--json <object> | --file <path>] [--out <path>]

Run a deck command (deck.run, runtime edge)
Inspect, lint and convert a Texuli deck on the shared v2 model: capabilities, the JSON Schema, layouts, lint, inspect, from-markdown and to-markdown. Pure compute; returns { result } with the command output (ok, issues, deck, markdown …).

Arguments (JSON object keys):
  command (required): "capabilities" | "schema" | "layouts" | "lint" | "inspect" | "from-markdown" | "to-markdown". capabilities, schema and layouts take nothing; lint, inspect and to-markdown take deck; from-markdown takes markdown.
  deck: object. A JSON deck (formatVersion 2) for lint, inspect or to-markdown.
  markdown: string. Deck Markdown (front matter, one section per slide) for from-markdown.

Limits: input up to 2100000 bytes, 10000 ms budget.
Example (What the deck format supports): texuli deck run --json '{"command":"capabilities"}'

----
Usage: texuli document run [--json <object> | --file <path>] [--out <path>]

Run a document command (document.run, runtime edge)
Create, validate, inspect, patch and convert a Texuli document (spec 0.7.0): capabilities, the JSON Schema, validate, inspect, a bounded RFC 6902 patch (at most 1000 operations), from-markdown, to-markdown and to-blueprint. Returns { result } with the command output; PDF and DOCX are document.export.

Arguments (JSON object keys):
  command (required): "capabilities" | "schema" | "validate" | "inspect" | "patch" | "from-markdown" | "to-markdown" | "to-blueprint". capabilities and schema take nothing; from-markdown takes markdown; every other command takes document.
  document: object. A Texuli document (format texuli-document, formatVersion 1).
  markdown: string. Markdown text for from-markdown.
  patch: array. RFC 6902 operations for patch (add, remove, replace, move, copy, test).
  tier: "developer" | "untrusted". The URL policy tier links and media are checked at (default untrusted).
  key: string. The node key for to-blueprint (default "document").

Limits: input up to 2100000 bytes, at most 1000 items, 10000 ms budget.
Example (Import Markdown): texuli document run --json '{"command":"from-markdown","markdown":"# Brief\n\nA fictional plan."}'

----
Usage: texuli document export [--json <object> | --file <path>] [--out <path>]

Export a document as PDF or DOCX (document.export, runtime node)
Write a Texuli document as PDF or DOCX bytes with the owned writers, links and media checked at the tier. Returns { result } with ok, mime, byteLength, base64 bytes (no files are written), diagnostics and, for PDF, pageCount. Needs Node.

Arguments (JSON object keys):
  format (required): "pdf" | "docx". The file format to write.
  document (required): object. A Texuli document (format texuli-document, formatVersion 1).
  tier: "developer" | "untrusted". The URL policy tier links and media are checked at (default untrusted).

Limits: input up to 2100000 bytes, 30000 ms budget.
