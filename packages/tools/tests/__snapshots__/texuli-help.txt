Usage: texuli <group> <verb> [--json <object> | --file <path>] [--out <path> [--overwrite]]
       texuli <command> [options]
       texuli help [<group>]

Operations (the @texuli/tools registry; the same names are MCP tools):
  catalog search            Search the component catalog
  catalog validate          Validate catalog manifests
  component get             Read a component manifest
  example search            Find component examples
  blueprint validate        Validate a blueprint draft
  blueprint theme           Apply a design system to a blueprint
  block list                List block types
  block schema              Read a block shape
  theme search              Search the theme library
  theme get                 Read a full theme
  theme preview             Preview a theme
  ds validate               Validate a design system
  ds compile                Compile a design system
  ds contrast               Report design-system contrast
  ds suggest                Suggest a design system
  ds import                 Import a design system
  ds diff                   Diff two design systems
  ds preview                Preview a design system
  ds save                   Save a design system to a file (node only)
  deck run                  Run a deck command
  document run              Run a document command
  document export           Export a document as PDF or DOCX (node only)

Commands:
  deck <command>            The deck commands (capabilities, schema, layouts, lint, inspect, from-markdown, to-markdown)
  document <command>        The document commands (validate, patch, from-markdown, to-pdf … with --out)
  ds init <file>            Write a new design-system document (--brand "<one-liner>")
  ds validate <file>        Validate a design-system document (ds.validate)
  ds compile <file>         Compile it to JSON, CSS, a Tailwind preset, DTCG or Tokens Studio (--format, --out)
  ds export <file>          Write one format to a file (--format, --out)
  ds preview <file>         A static SVG or HTML snapshot (--format, --out)
  ds diff <before> <after>  Compare two design systems (ds.diff)
  ds import <file|text>     Import DTCG, Tokens Studio, a role palette, a theme or a one-liner (--from, --out)
  ds check <file>           Check a design-system document: codes, guarantees, contrast report (--json, --render, --mode, --variant)
  mcp                       Run the local MCP server over stdio (every operation)
  init                      Wire Texuli tokens and CSS into a Vite, Astro or SvelteKit project
  theme list                List the theme library
  theme preview <id>        Show a theme's key tokens and its WCAG AA report
  theme apply <id>          Switch an initialized project to another theme
  add <component>           Copy a styled component's source into the app
  diff <component>          Show what an update of a copied component would change
  update <component>        Three-way merge a copied component with a new source

Input: one JSON object from stdin, --json <object> (--json - reads stdin) or --file <path>.
Output: JSON on stdout (exit 1 on a refusal), or --out <path> to write it to a new file inside the working directory (--overwrite replaces one).
Run texuli <group> --help or texuli <group> <verb> --help for details.

Usage: texuli catalog search [--json <object> | --file <path>] [--out <path>]

Search the component catalog (catalog.search, runtime edge)
Search the built, content-addressed Texuli component catalog by text, group and emit tier. Returns the catalog hash and file name, the match count and one summary per component (id, package, label, summary, tier, group, emit tiers).

Arguments (JSON object keys):
  query: string. Text to match against component ids, labels and summaries.
  group: string. An exact manifest group id, e.g. "display" or "forms".
  tier: "developer" | "untrusted". Keep only components this emit tier may place: untrusted is what agent output may use; developer is app-authored code.
  limit: integer. How many results to return (1 to 100, default 50).

Limits: input up to 4096 bytes, at most 100 items, 5000 ms budget.
Example (Cards an agent may place): texuli catalog search --json '{"query":"card","tier":"untrusted","limit":5}'

Validate catalog manifests (catalog.validate, runtime edge)
Validate one candidate catalog manifest, or a set (which also catches duplicate ids), without writing files. Returns valid and a list of diagnostics, each with a code, a JSONPath, a message and a hint.

  manifests: array. A candidate manifest set (at most 500).

Limits: input up to 1000000 bytes, at most 500 items, 5000 ms budget.

Usage: texuli blueprint validate [--json <object> | --file <path>] [--out <path>]

Validate a blueprint draft (blueprint.validate, runtime edge)
Validate a blueprint draft (a catalog tree, an array of trees, or a texuli-blueprint envelope, migrated first) with the catalog's checks: structure, sinks, tree limits, component ids, tiers, prop, block and document schemas, the envelope's designSystem (codes under $.designSystem), grammar and the frame root. Returns valid, status, tier, migratedFrom and diagnostics with stable codes.

Arguments (JSON object keys):
  draft (required): object | array. The blueprint: a catalog tree { id, props, children }, an array of trees, or a texuli-blueprint envelope (format, version, id, catalog hash from catalog.search, status, createdAt, updatedAt, generator, tree). At most 512 nodes. schema-form, canvas and spreadsheet nodes and data-source bindings are refused: this server has no validator for them.
  tier: "untrusted" | "developer". The tier to validate at: untrusted (agent output, the default) or developer (app-authored). A tier the draft declares is ignored.
  fragment: boolean. Accept any roots (a fragment). Default false: one frame root (layout-page, layout-doc, layout-deck, document, canvas or data-dashboard).

Limits: input up to 270336 bytes, at most 512 items, 5000 ms budget.

  id: string. A wrapped tree only: the envelope id (default "draft").

Limits: input up to 1318912 bytes, at most 512 items, 10000 ms budget.

Usage: texuli ds compile [--json <object> | --file <path>] [--out <path>]

Compile a design system (ds.compile, runtime edge)

  selector: string. css only: the scope selector (default [data-tx-ds="<id>"], or :root).
  dark: "class" | "attribute" | "media". css only: dark mode through the .dark class (default), [data-tx-mode="dark"] or prefers-color-scheme.
  mode: "light" | "dark". Compile one mode only (default: every mode the document declares).
  trust: "untrusted" | "developer". untrusted (agent or user documents, the default) refuses every data: URL; developer accepts capped data: fonts and images.
  variant: string. A variant the document declares under variants (e.g. "high-contrast").
  bases: object. Documents for extends: "id@x.y.z", keyed by "id@version". "texuli:<theme>" bases load from the theme library; nothing is fetched.

Limits: input up to 1048576 bytes, 10000 ms budget.
Example (Scoped CSS): texuli ds compile --json '{"document":{"format":"texuli/design-system","formatVersion":1,"id":"minimal","version":"1.0.0","name":"Minimal","color":{"brand":{"seed":"#4f46e5"}}},"format":"css"}'

Usage: texuli ds suggest [--json <object> | --file <path>] [--out <path>]

Suggest a design system (ds.suggest, runtime edge)
Suggest a starting design-system document from one seed color, up to three brand colors (seed, secondary, accent) or a logo as RGBA pixels (the dominant colors pick the seed). Returns valid, the document, the dominant palette for pixels, the key tokens of each mode and warnings.

Arguments (JSON object keys):

  count: integer. pixels only: how many dominant colors to report (2 to 12, default 6).
  id: string. The id of the resulting document (lowercase words joined by hyphens).
  version: string. The semver version of the resulting document (default 1.0.0).
  name: string. The display name of the resulting document.
  trust: "untrusted" | "developer". untrusted (agent or user documents, the default) refuses every data: URL; developer accepts capped data: fonts and images.

Limits: input up to 1048576 bytes, at most 65536 items, 10000 ms budget.
Example (From one seed): texuli ds suggest --json '{"seed":"#0e7490","id":"harborline","name":"Harborline"}'

Usage: texuli ds save [--json <object> | --file <path>] [--out <path>]

Save a design system to a file (ds.save, runtime node)
Validate a design-system document (as ds.validate does) and write it as two-space JSON to the explicit .json path you pass, inside the working directory: traversal, symlinks, dot directories and dotfiles, node_modules, package.json and an existing file without overwrite are refused. Local doors only. Returns saved, the relative path and bytes written, or errors with stable codes.

Arguments (JSON object keys):
  path (required): string. Where to write, relative to the working directory (e.g. design-systems/harborline.ds.json): a .json file outside dot directories and node_modules, never package.json.
  document (required): object. A design-system document: format "texuli/design-system", formatVersion 1, id, version, name, and optional sections (extends, color, typography, shape, space, elevation, surface, motion, layout, icons, components, assets, voice, accessibility, variants). texuli://design-system/acme is a full example.
  overwrite: boolean. Replace an existing file (default false: an existing file is refused).
  dryRun: boolean. Validate the document and the path, and write nothing.
  trust: "untrusted" | "developer". untrusted (agent or user documents, the default) refuses every data: URL; developer accepts capped data: fonts and images.
  variant: string. A variant the document declares under variants (e.g. "high-contrast").
  bases: object. Documents for extends: "id@x.y.z", keyed by "id@version". "texuli:<theme>" bases load from the theme library; nothing is fetched.

Limits: input up to 1048576 bytes, 10000 ms budget.

Run a document command (document.run, runtime edge)

Arguments (JSON object keys):
